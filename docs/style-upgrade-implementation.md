## 已实现的链路

```text
Style + 用户要求 + Material + Mood + Weathering
    → 普通文本归一化调用（存在自由文本时）
    → Deterministic Creative Intent Resolver
    → AI Palette → 验收 → AI Specification → 验收 → AI Render
                         ↓
                    确定性油漆匹配
```

归一化复用已配置的 Gemini 文本路线与内容安全筛查，不新增 Agent、工具循环或任务编排框架。Resolver 是纯数据合并逻辑，不调用模型。没有补充文本的预设直接适配默认值；旧版保存描述缺少明确要求来源时，在当前文本请求中补充归一化。

## 契约与优先级

- `creative-intent.v1` / `creative-resolver.v1` 冻结原始 Style、有效颜色、按属性的 hard/soft/free 约束、输入证据、裁决、覆盖记录及未解决项。
- `visual-palette.v3` 使用独立 `colorId` / `colorName`，用途角色允许重复。第一版容量为最多 32 种颜色，六个角色不构成六色上限。
- `repaint-specification.v3` 使用 `assignmentId` / `colorId`，一种颜色可以分配到多个部位或角色。颜色存在、装甲用途、引用、准确 HEX、明确比例及材质均在阶段转换时校验。
- `creative-source-normalization.v2` 要求每个颜色明确报告视觉重要性；未指定时使用 `unspecified`，明确大面积装甲色使用 primary / secondary，局部金色细边等仍使用 accent。视觉重要性不等于面积百分比。
- 下游收到行为字段和逐色 `allowedRoleSlugs`，不再收到原始 Style 的名称、两三色摘要、旧分类、原文证据或比例提示。角色选项与验收使用同一规则：明确主要装甲色只允许主装甲 / 副装甲用途。模型越界时拒绝并退款，不篡改其结果。
- 用户明确颜色覆盖对应的 Style 默认。色系、准确 HEX、颜色存在、视觉重要性、部位和比例分别约束；“蓝白搭配”不生成用户 50:50 强约束。
- 保存的自定义 Style 加新文本时，当前 Notes 或主动选择按属性与范围覆盖旧描述要求，保留未修改属性；旧约束标记为被覆盖并留下来源及裁决。同次 Notes 内的比例、HEX、Finish 矛盾仍拒绝。
- 比例带计算范围与来源。明确装甲 70:30 不挤占骨架或传感器；合计 100% 的限制只作用于同一范围。标记作为独立用途处理。
- 主动选择的材质与系统自动默认有不同来源。同属性的明确冲突没有可靠覆盖关系时会拒绝，而不是静默忽略。
- 原始 Style 和历史记录不被修改；下游模型只读取有效执行投影，覆盖掉的颜色或材质不会从原始 Notes / Style 再次进入提示词。
- 目录 Kit 保持几何；当前文本不能开放结构改造。EVA 的 `green chest accents` 已改为几何描述，旧数据在提示词边界进行相同的窄范围清理。

每个新 Concept 冻结有效意图、材质、Palette、Specification 和油漆推荐。历史 v2 记录继续按旧契约读取与执行；没有数据库回填或破坏性迁移。社区复制不带入原作者的私有描述及证据。

## 油漆与界面

油漆推荐改为按颜色 ID 关联，复杂度为 O(颜色数 × 目录样本数)。缺少合适 SKU 时保留视觉目标并显示混色说明；同一个 SKU 可覆盖多个足够接近的目标。

创作第二步显示 “Refine this style” 文本框，上限 2000 字符，解释明确颜色与比例的区别。自定义 Style、生成状态、Library、Paint Plan、公开展示均承接完整颜色集合；真实批准配色不显示臆造的 50:50 比例。Library 的 “What this build keeps” 显示有效用户要求及其来源，准确色值和排除部位也可追溯。

开发配置使用 `creation.v3` 文本模板；HD 继续使用现有 `render.v2` 与 Cloudflare Image 路线，不增加新环境变量或用户计费项目。

归一化版本由服务端完成记录验证，旧保存 Style 缺少当前版本记录时，从其所有者的原始描述进行一次普通归一化，和本次 Notes 共用请求，不改写原始 Style。缓存键包含归一化版本，历史作品继续读取已冻结结果。
