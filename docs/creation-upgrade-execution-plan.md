# 创作空间升级执行计划：Style 优化与 Custom Kit

日期：2026-10-11
状态（更新于 2026-10-12）：P0–P3 的 Style 核心改造与 P4–P6 的 Custom Kit 首版均已完成开发验收；开发后端为 `dev:hallowed-raven-873`。Custom Kit 的 8 次真实扫描与 4 个生成案例通过，开发功能已开放；未配置开关的部署默认关闭，生产环境尚未发布。具体改动和验证见 [Style 升级实施记录](./style-upgrade-implementation.md) 和 [Custom Kit 实施记录](./custom-kit-implementation.md)。

依据：

## 1. 执行策略与首版范围

先建立共用契约，先完成并交付 Style 优化，再让 Custom Kit 接入相同的 Palette、Specification、Render 与 Paint Plan 链路。

两次功能交付：

- **交付 A：Style 优化。** 官方目录 Kit 下，自定义 Style、预设 Style、预设 Style + 用户文本、自定义 Style + 补充文本都使用统一的有效意图契约。优先级与多色表达问题一起解决。
- **交付 B：Custom Kit MVP。** 用户上传一张参考图，扫描同时判断适用性和观察结构，用户可纠正并用文本提出修改；通过后使用已升级的 Style 与生成链路。

Custom Kit 与官方目录身份分开。普通小动物等无关主体拦截；兽形机甲、四足机器人、未知 IP 与原创机体按可见机体结构判断。

首版不包括第二张参考图、donor 部件图、多图融合、纯文本从零创建、CAD 或实体装配验证。不新增 Agent，不引入新的任务编排框架。

## 2. 阶段顺序与依赖

| 阶段 | 主要工作 | 前置依赖 | 完成标准 |
| --- | --- | --- | --- |
| P0 | 共用契约与回归样本 | 两份已确认方案 | 明确字段、来源、版本、冲突与验收规则 |
| P1 | Style 文本归一化与确定性 Resolver | P0 | 自定义 Style 与预设加文本都能形成同一种有效意图 |
| P2 | 多色 Palette、部件分配及下游升级 | P0、P1 | 多色不丢失；油漆匹配、Specification、Render、展示均能承接 |
| P3 | Style 创作体验、回归与交付 A | P1、P2 | 两条 Style 路径生成可用，历史作品正常，视觉案例通过 |
| P4 | Custom Kit 身份、私有上传与单次 Scan | P0、前期能力验证 | 单张参考可保存、扫描、拦截、纠正，并与官方 Kit 区分 |
| P5 | Custom Kit 文本修改与共用生成接入 | P2、P4 | 有效 Kit 参与 Resolver、分色、涂装计划与参考图渲染 |
| P6 | 两种 Kit × 两种 Style 验收与交付 B | P3、P5 | 四种组合、失败路径、版本与权限验证通过 |

正式交付顺序为 A 再 B。P4 的上传与扫描准备不必等待全部 Style 界面工作完成，但 Custom Kit 的正式生成依赖 P2 的完整下游契约，不能另建简化管线绕过。

## 3. P0：共用契约与回归样本

先定接口与语义，减少 Style 完成后为 Custom Kit 再做一次契约改造。

产出：

- 有效创作意图：几何、颜色、材质、图案、Mood 与 Weathering 分维度表达。
- 约束与来源：`hard / soft / free`、原始输入引用、覆盖关系、冲突和裁决记录。
- 颜色与部件：独立 `colorId`、`assignmentId`、部件组及用途角色；角色数量不限制颜色数量。
- 比例：计算范围、用户明确比例、风格默认比例与 AI 分配比例分开。
- Kit Source：catalog / custom 身份，以及有效 Kit、参考资产和扫描版本。
- 兼容策略：保留旧记录读取；新版写入前完成所有必要消费者的读取支持。

把以下案例建立为输入、期望约束和允许变化的回归样本：Arctic Ops + 蓝白、明确 70:30、多种主要装甲色、自定义 Rainbow、用户主动材质选择与文本冲突、单图只换色、肩甲加厚、背包展开、不适用主体、模糊机体、兽形机甲。

验收：能说明每一项要求从何而来、是否允许变化，以及不满足时在哪个阶段拒绝；AI 推测的颜色或比例不能冒充用户明确输入。

## 4. 前期穿插验证：单图与结构化扫描能力

在 P0 后、小规模实施前验证两个接口边界，验证结果供 P4、P5 使用，不改变先交付 Style 的顺序。

- 使用人工确认适用的单图样本，验证换色、肩甲轻微加厚、背包翼片展开和保持未编辑部位。
- 验证多模态文本模型是否能同时返回适用性、可见结构和未知区域，并符合 Kit Scan Schema。
- 比较参考图加文本与参考图加结构化意图的表现，记录原色继承、几何漂移、未展示结构补全和失败情况。
- 记录实际延迟、请求成本、输入限制与路线兼容性；模型选型与扫描定价据此确定。

这是内部能力实验，没有面向用户的开放入口。样本数量、费用范围与判定标准在运行前明确；本计划不代表已执行这些调用。面向用户开放前，P4 的适用性拦截必须完成。

## 5. P1：Style 归一化与 Resolver

打通两条主要输入路径：

| 路径 | 处理方式 |
| --- | --- |
| 自定义 Style | 原始描述 → 已有 Interpreter 的归一化能力 → 结构化 Style 与用户明确要求 |
| 预设 Style + 用户文本 | 预设默认 + 归一化用户修改 → 按属性覆盖、保留或增加要求 |

无补充文本的预设可直接进入默认适配；已有自定义 Style 加新文本，也按相同修改语义处理。

归一化负责理解文本，Resolver 只合并已结构化的数据。确定归一化的调用时机、复用方式及必要调用数，不用正则宣称完整理解任意描述。

实施要点：

- 识别颜色新增、替换、保留、排除，以及“仅允许这些颜色”的作用范围。
- 将颜色存在、色系、HEX、比例和部位分别约束。
- 用户明确审美要求覆盖对应 Style 默认；Mood 不改写强约束颜色。
- 材质、旧化等主动选择与自动默认保留来源区别；相互冲突的明确要求不得静默降级。
- 保存原始 Style，生成派生有效意图；不修改官方预设或已有自定义 Style 的历史版本。
- 模糊表达保留未解决状态与可理解的说明，不丢弃，也不自动解释成更强要求。
- 同一归一化接口为后续 Custom Kit 的文本几何修改预留字段；当前目录 Kit 不因此自动开放未授权改造。

验收：蓝白不被 Style 默认覆盖，也不被擅自固定为 50:50；70:30 仅在明确要求时成为比例目标；相同输入的 Resolver 裁决可复现。

## 6. P2：多色 Palette 与完整下游契约

完成颜色与位置解耦，按“先支持读取、后开放新版写入”接入：

1. 新版 Schema、标识和旧版读取适配。
2. Palette 支持独立颜色，Specification 支持多条颜色到部件的分配。
3. 油漆推荐、Paint Plan、Library、创建预览及相关公开输出按新标识关联。
4. Render 消费批准的有效意图、颜色和部件分配，移除已被覆盖的旧 Style 指令。
5. 全链路消费者通过后，开放新版生成写入。

角色继续用于用途分组，不再要求每个角色恰好对应一个 HEX。每个角色可容纳多个颜色，一种颜色可跨角色与部件使用。

加入跨阶段验收：有效颜色不能静默删除或替换；大面积装甲色不能仅放入传感器完成要求；assignment 不引用不存在的颜色或部件；强约束违反拒绝结果，软约束偏离记录原因。

油漆目录缺少 SKU 时保留视觉目标，返回混色或无匹配说明。评估颜色增多后现有匹配搜索的性能；兼容投影不能无声压缩多色信息。

完善快照与输入键：用户文本、Style 版本、有效 Kit 和 Resolver 版本变化时，相关 Palette / Specification 失效。历史作品仍使用历史快照。

验收：七种有效颜色能从 Palette 完整进入部件分配、Render 和展示；不同颜色共享装甲角色时油漆匹配不会覆盖；旧版作品继续可读。

## 7. P3：Style 体验与交付 A

在现有创作空间中完成自定义 Style 与预设加文本的端到端体验，所有 UI 遵循 `docs/ui-direction.md`。

用户应能理解有效颜色、允许变化部分、冲突以及重要覆盖结果。文本变化触发重新解析和必要阶段重生成，不误复用旧 Palette；保存原始 Style 与本次创作修改的边界保持清楚。

验收包含：

- 自定义 Style，包括 Rainbow 多色方案。
- 预设 Style 无文本，保持原有默认行为。
- 预设 Style + 蓝白、部位、明确比例等文本要求。
- 已有自定义 Style + 补充文本，修改生效且原始版本不被覆盖。
- 模型调用失败、约束冲突、重复请求、退款与历史详情。

以固定样本核对颜色保留、非授权结构保持和实际图片效果；数据契约正确不能代替视觉验收。Model DNA 的原色词清理可在此阶段作为独立小项处理，不扩展成机体目录重建。

检查通过后交付 A。Custom Kit 的后续工作复用这一稳定生成链路。

## 8. P4：Custom Kit 身份、单张上传与 Scan

建立属于用户的 Custom Kit 记录与版本，不把上传内容写成官方目录 `baseModels` 条目。

提供私有上传，复用现有媒体资产和 R2 生命周期；服务端校验恰好一张图、格式与可读性、用户所有权和资产版本。创建入口、记录和详情明确显示 Official Kit / Custom Kit 来源。

一次 Vision Scan 同时返回：

- `supported / unsupported / needs-better-reference` 适用性及依据。
- 可见部件、稳定部件 ID、可见状态和原始观察。
- 遮挡、未展示与不可确认区域。

服务端绑定并校验扫描结果后才允许进入主生成；普通动物、普通人物及无关图片不强行改造成机体。模糊机体提示更换参考，兽形机甲和原创机器人不按动物外形或未知 IP 拒绝。

原始扫描保留不变；用户纠正形成有效基线。更换图片使旧适用性和扫描失效，改 Style 或文本不自动重扫同一参考。

验收：不适用主体不触发 Palette / Render；伪造通过状态或复用他人/其他图片结果被拒绝；未知区域不编造为观察事实；重复扫描与失败按确定的计费、幂等和重试规则处理。

## 9. P5：文本结构修改与共用生成接入

复用 P1 的归一化与 Resolver，分别处理原图观察、识别纠正、用户结构修改和保留范围。用户颜色与几何修改可同时表达，各自作用于对应维度。

目录 Kit 与 Custom Kit 经适配后形成统一有效 Kit，进入相同的 Palette → Specification → Render。新增部件来自用户要求与生成提案，不能标记为扫描观察。

更新几何参考指令：未修改区域遵循图片，明确的局部修改在其范围内优先；参考原色不自动保留。避免“全局轮廓不变”抵消肩甲加厚或背包展开。

默认沿用参考视角。复杂多视角等现有渲染模式对 Custom Kit 的支持需逐项验证，未验证模式不自动开放。必需参考加载失败或路线不支持图像时显式失败并沿用既有退款/重试处理，不能静默纯文本继续。

Paint Plan 从批准颜色与有效部件分配产生。Library 和分享保留 Custom 身份，原始参考不随生成结果发布；不自动生成官方目录或 IP SEO 归属。

验收：一张参考图加文本能只换色、修改肩甲或展开背包，保留未编辑结构；结构修改或纠正会使相关分配和生成快照失效，但原始扫描可复用。

## 10. P6：组合验收与交付 B

必须验证四种组合，避免只证明各单独功能可用：

| Kit | Style | 重点 |
| --- | --- | --- |
| Official Kit | 预设 Style + 文本 | 颜色覆盖、比例与目录结构保持 |
| Official Kit | 自定义 Style | 多色完整承接与历史版本 |
| Custom Kit | 预设 Style + 文本 | 原色不污染新配色，局部修改按范围执行 |
| Custom Kit | 自定义 Style | 同时表达自定义结构与多色方案，Paint Plan 一致 |

另验收不适用输入、图像信息不足、兽形机甲、引用失效、权限、重复请求、调用失败、恢复与账本；同一结构可切换 Style，同一 Style 可应用不同 Kit。

每项代码改动执行适用的单元/集成测试；按仓库要求完成 `npm run lint` 与 `npm test`，前端路由变化执行 `npm run test:e2e:public`。上传、扫描与生成还需满足专用认证测试配置并实际验证用户流程。使用固定图像样本做视觉对照，记录费用、延迟与失败率，禁止以测试替身结果替代真实效果证明。

本地与开发环境验收通过后，按项目既有部署流程交付 B；两次发布分别可验收，历史读取与版本路由保留回退能力。

## 11. 阶段开始前需要确定的实施参数

| 参数 | 最迟确定阶段 |
| --- | --- |
| 归一化的调用时机、自由文本边界、复用和费用 | P1 |
| 契约版本、比例计算范围与验收方式、颜色容量及匹配性能边界 | P2 |
| 真实图像样本、验证调用预算与视觉通过标准 | 前期实验及 P3 / P6 验收前 |
| Vision 模型与 Schema 支持、扫描定价、缓存与失败规则 | P4 |
| 首版文本结构修改范围、Custom Kit 渲染模式与未知区域行为 | P5 |

这些参数在对应阶段解决，不需要因此阻止无依赖的契约、样本和兼容读取准备。双图等明确暂缓能力不列为首版前置条件。
