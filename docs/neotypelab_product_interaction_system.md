# NeotypeLab Product Interaction System

# Purpose

This document defines the interaction philosophy and product behavior system for NeotypeLab.

This document works together with:

- PRD documents
- Frontend Skill System
- UI Direction documents
- Design token systems

The goal is to ensure:

- Consistent product interaction
- Strong creative flow
- Mobile-first usability
- Community-oriented engagement
- Fast inspiration-to-output workflow
- Non-SaaS product behavior

---

# Core Interaction Philosophy

NeotypeLab is NOT:

- A traditional SaaS dashboard
- A generic AI image generator
- A prompt engineering tool
- A configuration-heavy enterprise platform

NeotypeLab IS:

> A future mecha repaint prototyping terminal.

Users should feel:

> They are experimenting with repaint concepts inside a future mecha R&D system.

---

# Product Experience Goal

The core experience target:

> Inspiration → Prototype → Save → Remix → Share

This loop should feel:

- Fast
- Visual
- Addictive
- Experimental
- Low friction
- Mobile friendly

---

# Product Structure Philosophy

# DO NOT Build a Traditional SaaS Homepage

Avoid:

- Large marketing hero sections
- Pricing-first pages
- Enterprise-style onboarding
- Long feature explanations
- Heavy CTA landing pages

The platform should feel more like:

- Pinterest
- Midjourney Explore
- Figma Community
- Armored Core Garage
- Mecha concept archive

---

# Primary Product Principle

# Interaction First, Marketing Second

Users should interact with the system immediately.

The product itself is the onboarding.

---

# Primary UX Objective

A first-time visitor should:

1. Discover a repaint concept
2. Want to try a variation
3. Start prototyping immediately
4. Experience the output quickly
5. Save/share/remix later

Without reading large amounts of marketing copy.

---

# Homepage Interaction Structure

# Homepage Is NOT a Landing Page

Homepage should function as:

> Explore + Prototype Terminal

---

# Homepage Layout

## Top Navigation

Minimal navigation only.

Recommended:

- Explore
- Prototype
- Library
- Styles
- Feedback
- Login/Profile

Avoid:

- Corporate navigation
- Enterprise sections
- Large dropdown systems

---

# First Screen Structure

The first screen should immediately expose:

## A. Live Showcase Grid

Large repaint concept previews.

Examples:

- RX78 EVA Style
- Cyberpunk Sazabi
- Desert Ops Barbatos
- Stealth Zaku

Goal:

> Immediate visual inspiration.

---

## B. Persistent Prototype Entry

A visible creation trigger must always exist.

Recommended labels:

- Initialize Prototype
- Run Simulation
- Start Build Concept

Avoid:

- Start Free Trial
- Generate AI Art

---

## C. Lightweight Filter Interaction

Allow quick exploration:

- Style DNA
- Base model
- Paint finish
- Weathering level

The homepage itself should feel interactive.

---

# Onboarding Philosophy

# The First Generation IS the Onboarding

Do NOT force users into:

- Long tutorials
- Registration walls
- Multi-step onboarding
- Enterprise setup flows

The first prototype interaction teaches the product.

---

# Guest Mode System

# Guest Generation Is Mandatory

First-time visitors should be able to:

- Select a base model
- Select style DNA
- Generate a prototype preview

WITHOUT account creation.

---

# Why

This product depends on:

> Emotional creative momentum.

Many users arrive from:

- Reddit
- Facebook
- Pinterest
- YouTube
- Discord

If forced to register before interaction:

- Curiosity collapses
- Conversion drops
- Shareability weakens

---

# Registration Trigger Strategy

Require login only when users attempt to:

- Save prototype
- Publish showcase
- Remix builds
- Use HD generation
- Purchase credits

---

# Creation Flow Philosophy

# Structured Creativity

Users should NOT write large prompts.

Users should interact through:

- Presets
- Selections
- Cards
- Chips
- Toggles
- Controlled notes

---

# Core Creation Flow

# Step 1 — Select Base Model

Interaction Type:

- Large visual cards

Card content:

- Preview image
- Model name
- Series
- Complexity level

Goal:

> Immediate recognition.

---

# Step 2 — Select Style DNA

Interaction Type:

- Horizontal scroll cards
- Style previews

Examples:

- EVA-inspired
- Military Prototype
- Cyberpunk
- Industrial Mecha
- Stealth Black

Goal:

> Inspire experimentation.

---

# Step 3 — Select Paint Finish

Interaction Type:

- Chips
- Compact cards

Examples:

- Matte Finish
- Semi-gloss Finish
- Gloss Finish
- Metallic Finish
- Pearl Finish
- Candy Coat

Goal:

> Choose the sprayable surface state and guide paint product matching.

---

# Step 4 — Select Weathering

Interaction Type:

- Segmented control with optional effect chips

Options:

- Clean
- Light
- Heavy

Optional effects:

- Dry Brushing
- Chipping
- Wash
- Rust Effects
- Dust Effects
- Burn Marks

Goal:

> Add use, time, and battle-wear cues without changing paint selection.

Weathering should influence preview rendering, estimated effort, skill level, and small technique tips. It should not affect paint library matching or base paint decisions.

---

# Step 5 — Controlled Notes

Interaction Type:

- Small text input

Limit:

- 50–100 characters

Purpose:

- Give users ownership feeling
- Preserve output consistency

Example:

```text
More aggressive visor
Add orange warning decals
```

Avoid:

- Full prompt engineering
- Multi-line prompt systems

---

# Step 6 — Credit Confirmation

Before generation:

Show exact cost clearly.

Example:

```text
Prototype Preview: 2 credits
HD Render: +5 credits
```

No hidden costs.

---

# Step 7 — Result Experience

Result page must feel rewarding.

Must include:

- Large preview image
- Color role breakdown
- Paint finish
- Weathering tips
- Paint mapping
- Save
- Remix
- Share
- Feedback

The result itself becomes a social object.

---

# Interaction Design Principles

# Fast Feedback Loops

Users should never feel stuck in setup.

The platform should encourage:

> Rapid visual iteration.

---

# Low Friction Exploration

Users should feel safe trying:

- Weird combinations
- Experimental styles
- Different weathering
- Alternative color logic

Without overwhelming configuration.

---

# Infinite Exploration Psychology

The interaction loop should naturally create:

> “One more variation.”

This is a core retention mechanic.

---

# Mobile Interaction System

# Mobile Is a Primary Platform

Users should be able to:

- Discover inspiration
- Prototype concepts
- Save builds
- Share concepts

Entirely from mobile.

---

# Mobile Creation Philosophy

Mobile should feel like:

> A fast tactical design console.

Not:

> A compressed desktop dashboard.

---

# Mobile Interaction Rules

Required:

- Bottom navigation
- Sticky CTA
- One-thumb flow
- Large touch targets
- Horizontal preset browsing
- Quick transitions
- Minimal typing

Avoid:

- Large forms
- Multi-column layouts
- Complex sidebars
- Desktop tables
- Tiny toggles

---

# Community Interaction System

# Community Is Part of the Product

Users are not passive consumers.

They are:

- Remix creators
- Inspiration sources
- Data contributors
- Style explorers

---

# Community Actions

Users should easily:

- Save
- Remix
- Like
- Share
- Compare
- Fork concepts

---

# Remix Philosophy

Remix is a core feature.

Example:

```text
RX78 EVA Variant
→ Desert Ops Remix
→ Heavy Weathering Remix
```

The platform should encourage:

> Creative branching.

---

# Feedback System Philosophy

Feedback is NOT just support.

Feedback is:

> A data expansion engine.

Users should be able to report:

- Missing models
- Missing styles
- Bad paint logic
- Unrealistic finish rendering
- Poor masking logic

Feedback UI should feel lightweight and fast.

---

# Showcase Interaction Philosophy

# Showcase Pages Are Discovery Engines

Users should continuously encounter:

- New style combinations
- Unexpected remixes
- Community trends
- Build inspiration

The showcase experience should feel:

- Endless
- Visual
- Collectible
- Curated

---

Preferred terminology:

- Prototype
- Simulation
- Style DNA
- Paint Finish
- Weathering
- Reactor Output
- Build Concept
- Paint Mapping
- Saved Hangar
- Remix

Avoid:

- AI art generation
- Prompt engineering
- Create image
- Magic AI wording

---

# Emotional Interaction Goal

The user should feel:

> I am testing future repaint concepts inside a real mecha development system.

NOT:

> I am using a generic AI website.

---

# Monetization Interaction Philosophy

# Credits Should Feel Natural

Credits are not just payment.

Credits represent:

- Simulation capacity
- Rendering cost
- Prototype resources

However:

- Costs must remain understandable
- Pricing must remain transparent

Avoid:

- Confusing gamification
- Hidden consumption
- Aggressive monetization popups

---

# Retention Philosophy

Retention should come from:

- Exploration
- Creativity
- Remix culture
- Community inspiration
- Personal collection building

NOT:

- Notifications spam
- SaaS lock-in
- Forced onboarding

---

# Product Feeling Summary

NeotypeLab should feel like:

- A mecha repaint laboratory
- A future tactical design system
- A concept archive
- A spray-planning workstation
- A community remix ecosystem

The interaction should feel:

- Immediate
- Cinematic
- Structured
- Fast
- Mobile-friendly
- Inspiration-driven
- Highly visual

The user should never feel:

- Over-configured
- Overwhelmed
- Locked behind forms
- Forced into enterprise SaaS flows
- Like they are writing prompts into a chatbot
